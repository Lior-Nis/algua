# Decision log

## 2026-10-05 — Initial distillation

Inputs: Story 2.2, issue #685, the Epic 2 plan in `epics.md`, Story 1.4's contract and review, the
code at `e875b6d`, a read-only copy of the production registry (schema v48), and a probe that ran the
32 test files driving transitions and recorded every allocation-shedding call (797 passed; 53 calls).

Entry points. Only `registry transition` takes a strategy off the paper lane today. Every production
allocation-shedding store call goes through `transitions.py:97`. `backtest_run.py:105` cannot reach a
paper exit, because the lifecycle has no paper-to-`backtested` edge. `paper promote` and the raw
`forward_tested <-> paper` edges stay on the lane. `_REVOKE_ON_EXIT` is exactly the set of allowed
edges that leave a lane's operating stages.

Decisions:

- **Selection happens inside `transition_strategy`, by default, for both lanes.** It mirrors the
  `_default_forward_certificate_verifier` seam: a lazy import of `lane_exit.select_exit_guard`.
  Story 2.4 (`paper handoff`) and Story 2.6 (the live pause) will add callers, and the repeated
  finding of Stories 1.2, 1.3c and 1.3d was a second path in, so a drain that a caller can forget
  to inject is not acceptable. Selecting from the same record the compare-and-swap checks also
  removes today's two-read gap between the CLI's guard choice and the exit's source stage.
  Rejected: a CLI-injected selector, which has less test churn but leaves every future caller
  unguarded unless it remembers.
- **The `exit_guard` parameter becomes `exit_guard_selector`**, with no alias. The store's
  `apply_transition(exit_guard=...)` and `_assert_flat_for_bench` are untouched, so the protected
  positions check, the dust rule and both "not flat" messages are reused as they are.
- **Go-live gets the paper guard.** Its source lane is paper, the store already checks paper
  positions on it, and its resting orders are paper orders. The live gate's walls run first, so an
  unauthorized attempt never touches the venue. The challenge is consumed only after the re-check,
  so a refused drain does not burn the signature.
- **Sync, then skip the cancel when the ledger holds a material position.** The drain ingests first
  and cancels only when the exit could succeed. An exit attempted while liquidation offsets are
  resting would otherwise cancel them and then be refused on positions. That is the production state
  of the last legacy tenant on 2026-10-05: kill-switched, 3.552855 UNH, a resting sell offset. The
  skip check reuses the bench rule's expression; a test pins their equivalence instead of editing
  the protected store.
- **Observe after the cancel, sync after the last observation.** A second open-order read after the
  cancel feeds the under-lock answer, and the final ingest's `until` is read after it. An order that
  could not be cancelled therefore cannot fill unseen between the last ingest and the under-lock
  re-list (a gap the live guard keeps). The under-lock re-list stays, as AC2 requires.
- **The skipped and never-run states refuse under the lock.** An exit can commit only through a
  completed drain. This guards against a concurrent ingest flattening the ledger after a skip, and
  against a caller that never ran the drain.
- **Broker clock only.** The drain uses `tick_clock` for normalization but refuses its local-clock
  fallback. The ingest stores `until` as the shared paper cursor, and a skewed local time can skip
  fills for good; a refused exit can simply be retried.
- **Stranded-order recovery runs after each ingest**, which is the paper operator's own pairing. A
  crash-stranded order's fill is otherwise unattributed and invisible to the positions check.
- **Failure classification.** Missing credentials raise `TransitionError` (`wrong_stage`), like the
  live drain-unavailable branch. Venue-side drain failures are audited and raise an actionable
  `BrokerError` (`broker_error`), the code the live guard's raw broker failures already produce.
  `sqlite3.Error` passes through unaudited and keeps its retryable `db_unavailable`. No new codes.
- **Nothing is audited under the write lock.** `audit.log.append` commits, so an audit call there
  would commit the exit half-way. An under-lock re-list failure is rolled back and reported only by
  the envelope; the pre-lock failures cover AC3's audit requirement.
- **A cancelled-orders audit row** (`paper_exit_drain_cancelled`) records every venue mutation a
  registry command makes, including on a refused exit. This is additive; there is no schema change.
- **No break-glass, no short-circuit.** Paper has one credential set, and `paper flatten` needs the
  same credentials. Rejected: skipping the venue for a strategy with no order rows. It is sound
  (rows are written before every POST, #249), but it adds a second guard shape and weakens AC3's
  plain rule. The test churn is handled by an explicit, non-autouse empty-venue fixture instead.
- **Every paper-lane exit takes `operator.lock`.** Without it, a timer-driven cycle whose pre-tick
  stage check passed can submit for the strategy after the exit commits, which is exactly #685's
  orphan. Today only retirement and `paper -> candidate` take the lock; `paper -> dormant` and
  go-live join them. The existing message is kept byte-identical, because `live -> retired` is a
  live exit, and the two new edges get an accurate one. The context manager is renamed
  `operator_transition_lock`.
- **Placement.** `ingest_paper_venue` and `recover_stranded` move to `algua/execution/venue_sync.py`
  (they reach only the ledger and the audit log, so no new package edge). The paper guard and the
  shared selector join `lane_exit.py`. `paper_scoped_cancel` stays in the CLI helper, and the guard
  cancels in the live guard's own shape. All three touched execution/operator modules join
  CODEOWNERS and the integrity-critical set.
- **No kill switch.** A refused exit leaves the strategy on the lane, unchanged apart from cancelled
  orders, and the next tick re-plans it.

Coordination: Story 2.1 also edits `transitions.py` (`_validate_live_gate`) and `registry_cmd.py`
(challenge issuance). `transitions.py` is unpinned at 277 lines, and the ratchet forbids it reaching
300. This story budgets it to 290, and the second story to merge rebases or carves. This story
frees about 60 lines in `registry_cmd.py`.

Residuals recorded: the live guard's two gaps (file one issue, since AC6 keeps the live guard
unchanged); activity-feed visibility lag; paper commands run by hand outside the operator wrapper;
an under-lock re-list failure appearing only in the envelope.

Self-validation: each capability has an observable success condition. The companion fixes the edge
set, the call order, the guard algorithm, every message, audit action and code, the placement,
size and protection, the tests with their mutation checks, and the readiness invocations. No choice
is left to the implementer except the test fixture's name.
