# Decision log

## 2026-10-05 — Initial distillation

Inputs: Story 2.1 (ten ACs), the owner decisions on #624 (item 2) and #682, the Story 1.3d
contract, the code at `e875b6d`, and a read-only probe plus a backup-copy rehearsal of the
production registry (user_version 48: 21 research rows, all agent, `StoreBackedProvider`,
`measured`, `pit_override=0`, default thresholds; no forward rows, deployments, holdout reuse,
live or actor challenges).

Vocabulary:
- The vocabulary lives in `algua/registry/relaxations.py` (pure, protected), not in
  `algua/research`: it also holds the moved `guard_agent_relaxations` (the `promotion.py` carve)
  and feeds the registry-side predicate. It imports `GateCriteria`/`ForwardGateCriteria` and reads
  their dataclass defaults at call time, so a default is never copied.
- A threshold is unrelaxed only when provably at least as strict as its default (`>=` or `<=`); a
  non-finite value is a relaxation. Research needs this (a `NaN` advisory threshold disarms its
  check yet the row can pass). The forward guard reuses the same function, so the direction table
  exists once; for finite inputs its refusals and message are byte-identical, and the single delta
  (an agent's `NaN` forward threshold, which today can only yield a fail-closed row, is now refused
  at preflight) is accepted and recorded rather than kept as a second comparison rule.
- `--demo` counts (`demo_data`): a gate on synthetic bars is not a gate at its protected default.
  The merge-back drainer can pass `--demo` (`MERGEBACK_DEMO`), so this matters on the agent path.
- A human research run is never at its protected defaults even with no flag: it skips the
  reproducible-source, cost-floor, feature-lookback and gated-universe walls and the seeded,
  rate-capped agent family path, which the code itself calls exploration exemptions. Every human
  research row records `agent_walls_waived`. Rejected alternative: one token per skipped wall,
  computed by evaluating each agent wall for a human run; it duplicates four predicates inside a
  pinned module, and missing one is exactly the "second path in" the readiness rules warn about.
  Nothing is lost: a human wanting a live-eligible research gate runs `--actor agent`, which needs
  no signature. This extends AC1's list; the owner may revisit it like the `--demo` call.
- `--new-family` records `new_family` only when honored (a human run); the agent path ignores the
  flag, so an agent row records nothing for it, which also keeps runtime recording consistent with
  the migration rule for agent rows.
- `--allow-holdout-reuse` counts when given, overlap or not (the story's rule: a relaxation flag
  was signed). `--windows`, `--holdout-frac`, `--universe`, `--delistings`, the snapshots and the
  window are evaluation inputs, not relaxations: the walls that bind them (the 63-observation
  floor, `pit_required`, held-into-gap fail-closed) still apply at their defaults.
- A human `paper promote` at default thresholds records `[]`: the forward gate has no
  actor-dependent wall besides the thresholds.
- One table classifies every parameter of `research promote`, `promote_task` (also `research
  run-all` and the merge-back seam) and `paper promote`; the test requires set equality, so a stale
  or missing entry both fail.

Schema:
- The column reaches fresh and existing registries through one guarded ALTER (the v48 tick-link
  precedent), with a CHECK for the canonical array shape (rehearsed: SQLite accepts and enforces
  it on ALTER). A BEFORE INSERT trigger requires the value and enforces vocabulary, element type
  and strict ascending order (CHECK cannot hold subqueries); it repeats the shape test first so
  `json_each` never sees malformed text. A `BEFORE UPDATE OF relaxations_json` trigger makes the
  value immutable, including NULL → value. The tables keep their other mutations (`consumed`, FDR
  relabels). No delete trigger: nothing deletes these rows and a DB writer is outside the threat
  model.
- Vocabularies are literal in the DDL with a tie test, so `migrate()` never imports the research
  stack; the classifier imports the vocabulary lazily, only when there is a row to classify.

Migration:
- Classification runs once per table, guarded by the absence of that table's immutability trigger,
  in Python (SQLite's `json_extract` rejects the `NaN` literal older `decision_json` can hold). Each
  UPDATE carries `relaxations_json IS NULL`, so a concurrent migrator's late UPDATE matches no row
  and fires no trigger.
- Only rows whose own columns prove the set are classified: agent research rows with all four
  `decision_json` thresholds, the observations column and a known provider; agent forward rows that
  carry the LCB check (the confidence was agent-guarded from the commit that introduced it, #432).
  Human rows of both tables stay NULL (the human forward confidence is recorded nowhere on a passing
  row). A `null` threshold stays NULL: `+inf` and `NaN` both serialize that way.
- Rehearsal on a production backup: 21 → `[]`, nothing unrecorded, no forward rows; idempotent;
  other columns byte-identical.

Predicate:
- `verify_live_qualification` wraps the certificate verifier and then runs the predicate; both
  ceremony call sites use it, so an injected verifier replaces only the certificate step. The
  certificate is the row id the verifier returns, accepted only if it belongs to the strategy and
  its active deployment; anything else reads `unrecorded`. No active deployment makes both sides
  `unrecorded`.
- Refusal is a `TransitionError` subclass with code `live_qualification_relaxed`, non-retryable,
  four-key envelope, fixed message naming each row and token. The challenge's printed certificate
  summary gains `deployment_id`, `research_gate_id` and both (empty) sets; the signed bytes are
  unchanged.
- The legacy-cohort certificate branch stays: the predicate already refuses it (no deployment), and
  deleting it would rewrite about twenty verifier unit tests that the Story 1.4 legacy-path removal
  will retire anyway.
- `run_gate` takes the research set from its one production caller, as it already takes `actor`,
  `criteria` and `allow_non_pit`; `run_forward_gate` computes the forward set from the criteria it
  evaluates. The store takes the canonical string and imports no vocabulary; the triggers validate.

No raw way in (#682):
- `transition_strategy` refuses `backtested -> candidate` and `paper -> forward_tested` for every
  actor from one table, as a plain `TransitionError` (`wrong_stage`) like the intake refusal and the
  1.3d frozen forward refusal, rather than a new code. The `paper -> candidate` back-step stays:
  the owner decision concerns the forward edges named in #682, and intake's candidate-episode check
  already refuses a back-stepped candidate without a fresh gate.
- The now-unreachable token branches, `_validate_shortlist_gate`, `_validate_forward_gate`, the
  forward half of `refuse_frozen_deployment`, and the two `find_consumable_*` finders (their only
  callers) are deleted; the store's consume parameters on `apply_transition` stay as a follow-up,
  because removing them touches modules the story does not otherwise edit.

Size and protection:
- Carves instead of pin raises: `capture_gate_fail_experience` → `gate_fail_capture.py`;
  `guard_agent_relaxations` → `relaxations.py`; the deleted finders free `store/gate.py` and
  `repository.py`. Each touched pin is lowered to the exact new size.
- New modules and `gate_fail_capture.py` (it holds the registry connection inside `promote_task`)
  are CODEOWNERS-protected and in the integrity-critical set; `cli/registry_cmd.py` joins them
  because it holds the issuance check and the completion closure (precedent: `paper_cmd.py`,
  `research_cmd.py`).

Exploration:
- AC8 is proved by golden challenge strings computed at the baseline for a fully relaxed research
  run and a relaxed paper run, inertness tests (varying only the recorded set leaves every other
  column, the run row and the stage history equal), and the existing relaxed-human tests passing
  with only added assertions.

Self-validation: each capability has an observable success condition; the companion carries the
exact vocabulary and CLI table, the DDL and triggers (the protected schema review), the migration
rules with production counts, the recording seam, the predicate with its call sites, code and
message, the raw-edge refusal, the entry-point inventory, the AC8 proofs, placement, pins,
protection, the test and mutation matrix and the churn list; no choice is left to the implementer.
