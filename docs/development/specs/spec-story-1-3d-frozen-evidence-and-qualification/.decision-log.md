# Decision log

## 2026-09-30 — Initial distillation

Inputs: Story 1.3d, parent Story 1.3, the sprint change proposal, the artifact-freeze design, the
Story 1.3b/1.3c contracts and a code map of the Story 1.3c branch.

- An attempt is every phase dispatch the supervisor decided to run a child for, recorded once after
  the supervisor has fully judged it; supervisor-settled phases keep their existing records. This
  follows from Story 1.3c's authoritative supervisor verdicts, which mean not every phase launches.
- One append-only row per attempt, written at attempt end and committed immediately, not a
  begin/end pair or an updateable status: a crash leaves no row, and nothing can be updated into
  success.
- The tick-to-invocation link is a column on `tick_snapshots` guarded by a BEFORE INSERT trigger, a
  partial unique index and an update-abort trigger. One INSERT is atomic, so a tick cannot exist
  without its link or a link without its tick; enforcement lives in one protected place instead of
  every writer.
- Identity by immutable reference (deployment → artifact → descriptor), not copies, so there is
  nothing to keep consistent.
- The canonical request bytes are stored (no bars) so a recorded request can literally be replayed;
  roughly 10–20 KiB per request. Bars are recovered from the immutable data snapshot and checked
  against the recorded bytes digest.
- Replay is a test helper built from production primitives; no replay command in this story.
- One promotion chokepoint supplies identity: working-tree unchanged, frozen from the descriptor
  with fresh content verification; the human-actor challenge binds that identity.
- `frozen_qualification_pending` is removed; the raw transition edge keeps refusing frozen
  deployments as a `wrong_stage` TransitionError so `paper promote` is the only way to
  `forward_tested`. Go-live stays refused until Epic 2.
- No backfill of 1.3c-era ticks, no whole-table tick immutability, no GC or leases, no order-intent
  linkage.

Self-validation: each capability has an observable success condition; the companion carries the
exact DDL and triggers (the protected schema review), the attempt definition, recorder seam,
admissibility rule, promotion chokepoint and replay procedure; no choice is delegated to the
implementer.

  the recording code; the churn list; v48 is forward-only with a rollback runbook note.

## 2026-10-01 — Review amendments

The implementation review's findings on the evidence schema and its contract, applied in place to
v48 (not yet deployed; production is v47), so no new schema version:
- `result_kind` ↔ phase CHECK: rows are append-only, so a recorder bug would write permanent bad
  rows; the kind is now enforced by construction. Derived from the dispatcher: Phase A succeeds only
  with `early_no_decision` or `snapshot_required` (a supervisor-found breach launches no child, and
  a child's breach never matches the no-decision or snapshot verdict); Phase B with
  `late_no_decision`, `decision` or `risk_failure` (a weight-only breach). `PHASE_RESULT_KINDS` in
  `algua/contracts/frozen_evidence.py` holds the sets, `FrozenAttempt` refuses any other kind for
  its phase, and the table CHECK replaces the phase-blind column CHECK. The forward-evidence
  filter's `phase = 'b'` join clause stays as defence in depth.
- Vocabulary tie test: `tests/test_frozen_evidence_schema.py` parses the DDL's CHECK lists and
  requires them equal to `FROZEN_FAILURE_CODES` and `PHASE_RESULT_KINDS` (and the recorder's kinds
  to `ATTEMPT_RESULT_KINDS`); a value added on one side only fails. It also pins §2's DDL to the
  code verbatim.
- §1: the Phase B captured-state encoding check inside the supervisor's verdict (`_late`) is a
  supervisor refusal of its own input (no row); an `encode_request` failure inside the attempt is an
  attempt with no request bytes.
- §2 `diagnostic`: the raised `FrozenTenantFailure`'s sanitized, bounded diagnostic, equal to
  `process_diagnostic` only for process failures.
- §2 `stderr_truncated`: the 64 KiB stderr capture was cut, distinct from the diagnostic's own
  `stderr_truncated=true` head-truncation marker.
- The v48 rollback note is recorded in the operator runbook (`deploy/systemd/README.md`).
- Story 1.3c's contract marks `frozen_qualification_pending` superseded by §5; the architecture map
  says only child-launching attempts are recorded.
- Promotion identity (§5): `run_forward_gate` compared the identity only with its own deployment
  row, so a direct caller could evaluate unverified content. `PromotionIdentity` is now an opaque
  value only the chokepoint can mint (`promotion_slot` for frozen, after fresh verification;
  `promotion_identity` for working-tree, after the manifest check), and it is the gate's only input.
  The later working-tree resolution refuses if the epoch changed after the slot, so no frozen
  content is verified after authentication. A frozen human challenge also binds `deployment_id` and
  `manifest_digest`; working-tree and legacy challenge bytes are unchanged.
- Dismissed: an explicit id of -1 or a REPLACE/DELETE of a tick row (not reachable from any code
  path; a database writer is not a trust boundary); replay tests mock environment verification (the
  real environment is covered by the promotion tests and the opt-in real-environment test); a
  dependency-change test (tripwires prove the checkout identity is never computed on frozen paths).
- Deferred: raw `registry transition --to forward_tested --actor human` is unauthenticated and skips
  the forward gate for non-frozen strategies (pre-existing, #682).
