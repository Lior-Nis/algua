# Decision log

## 2026-09-30 — Initial distillation

Inputs: Story 1.3c, parent Story 1.3, the approved sprint change proposal, the artifact-freeze
design, Story 1.3a/1.3b contracts and a code map of `origin/main` `216c8ec`.

- Every new paper admission is frozen and working-tree admission is removed, rather than adding an
  opt-in switch or a second admission path. Existing working-tree and legacy tenants are untouched
  until controlled migration. Consequence accepted: a frozen deployment admitted before Story 1.3d
  accrues ticks that 1.3d's linkage rule will not credit, so its evidence clock effectively starts
  when 1.3d lands; 1.3d is the next story.
- Intake prepares with the Story 1.3b preparation and then verifies offline, instead of consuming a
  separately prepared descriptor: it reuses the existing clean-`HEAD` qualification, needs no new
  descriptor index, and keeps "prepare before the write transaction" literal.
- Two children per decision tick: the supervisor resolves the venue belief before Phase B instead of
  running Phase B once more to receive `venue_belief_required`. Phase B checks drawdown before
  belief either way, so the outcome is identical and the in-process three-step handshake stays for
  working-tree tenants.
- The supervisor computes closed bars for the sizing snapshot with the extracted Phase A helper and
  cross-checks the child's `decision_ts`, instead of widening the Story 1.3a result type.
- The supervisor's view of a frozen tenant is the recorded `resolved_config` validated by the
  current `StrategyConfig`; it never imports the tenant module from the checkout.
- Floats cross as `float.hex` strings: exact, and able to carry the NaN/inf marks that the breach
  fixtures need, while JSON itself never contains a non-finite number.
- Arrow IPC instead of Parquet: lossless NaN handling without null conversion, no row-group or
  statistics choices, deterministic uncompressed bytes. Both satisfy the story's Parquet/Arrow rule.
- `-I -B` without `-S`, bootstrap via a fixed `-c` constant: `-I` removes cwd, user site and
  `PYTHON*`; site processing is needed to load the environment's own site-packages, which Story 1.3b
  certified.
- A new stdlib primitive owns process-group teardown (SIGTERM, 2 s grace, SIGKILL, reap) and stderr
  truncation; the protected `run_bounded` used by uv provisioning is not changed.
- Content is verified offline once per digest per supervisor process; no lease, because Phase 1
  never removes published content. A future garbage collector must introduce one.
- Child planner refusals (input or binding) become the tenant failure `frozen_planner_rejected`,
  unlike the in-process `ValueError` that aborts a cycle; a child's risk failure keeps `RiskBreach`
  semantics so breach effect traces match.
- Offenders in `check_mark_freshness` are sorted so breach text is identical across fresh processes
  whose hash seeds differ; only message order changes.
- No schema change and no invocation evidence: both belong to Story 1.3d.

Self-validation: each capability has an observable success condition; the companion closes wire
bytes, launch, limits, validation, failure classification, admission, routing, promotion refusal and
placement; no choice is delegated to the implementer.

## 2026-09-30 — Readiness corrections

The independent readiness review (NOT READY: 1 blocker, 7 major) was applied to the companion:

- B1: the supervisor view is decoded strictly (constructors for `CapacityLimit` and
  `ExecutionContract`, exact-type checks, dump-back and `config_hash` equality), because
  `StrategyConfig` rejects a raw `execution` mapping by design (#344); named `FrozenStrategyView`.
- M1: the wire carries the *recorded* config with its own universe; the gate universe travels only in
  `gate_universe`, so Phase A's universe re-hash is unchanged.
- M2: the canonical encoder and frozen-wire constants move to one pure `algua/contracts` module
  shared by registry and child; the import contract no longer forbids `algua.config`, which
  strategy loading legitimately reaches.
- M3: a planner port on `TickHooks` with an in-process default. The frozen port answers a pending
  venue belief without a child, so `run_tick`'s handshake is untouched and ticks still launch at
  most two children. This supersedes the earlier "resolve the belief before Phase B" wording.
- M4: one `resolve_paper_tenant` replaces every checkout load on the paper tick path; promotion
  refuses before any checkout hashing; the live lane refuses inside `resolve_tick`.
- M5: `FrozenTenantFailure` is the single exception isolated from inside `run_tick`; codes flow via
  its `code` attribute; the `run-all` entry shape is frozen for Story 1.3d.
- M6: supervisor pre-launch checks and child exit code `3` make `frozen_content_unsupported`
  observable; the entry-point name and exit codes are part of wire v1.
- M7: the parity harness copies the working tree into a test bundle and relies on the child's
  module-origin check; one opt-in real-environment test.
- Minor items folded in: teardown order with `waitid(WNOWAIT)`; split modules over the ratchet
  floor; intake `refused` key and injectable preparation; `request_id` shared by both phases;
  parity defined over canonical encodings plus effect traces; `snapshot_id` stays out of the wire;
  `paper run` refuses frozen deployments; named code constants; verification in preflight.

## 2026-09-30 — Implementation amendments

- A weight-rule violation found by the supervisor's rerun of `validate_decision_weights` keeps
  breach semantics (`PlannerRiskFailure`), matching the in-process planner, instead of
  `frozen_result_invalid`; every structural or consistency mismatch stays `frozen_result_invalid`.
- The supervisor additionally re-derives the Phase A decision timestamp, no-decision states and the
  late state (including the persisted peak, which only ratchets up) and requires the child's to
  match, so a child cannot forge a peak that later trips the drawdown breaker.
- Exact parity required removing three sources of cross-process difference in shared planner and
  risk code: sorted reconcile text, symbol-ordered realized-gross summation and ASCII-only breach
  messages (the §7 sanitizer would otherwise strip an em dash). A test pins ASCII breach text.
- An unencodable supervisor input (for example a naive timestamp) is reported as
  `frozen_planner_rejected`, the closest existing code, rather than adding a new one.
- Child exit code `2` (undecodable request) is part of wire v1 and maps to `frozen_exit_abnormal`.

## 2026-09-30 — Review corrections: the supervisor owns the strategy-free walls

The review found that the supervisor trusted the *kind* of result a child chose: a child could
answer a decision where the planner breaches on drawdown, reconcile, realized gross or stale marks,
or report a ready strategy warming, and a false `stale_marks` claim would engage the account-wide
halt. The risk walls also ran only in the bundle's frozen copy, so a platform fix to a wall never
reached frozen tenants.

- Strategy-free risk walls are re-derived by the current supervisor and are authoritative (§7).
  The planner's strategy-free parts became shared functions (`validate_early` without a strategy,
  `early_verdict`, `verified_phase_a`, `late_verdict`) called by the in-process planner and the
  supervisor alike; a golden master pinned before the carve proves the in-process outcomes, texts
  included, unchanged.
- A breach the supervisor finds is returned before any child is launched for that phase, rather
  than after running one: a child that crashes or times out cannot mask a breach, and a phase whose
  outcome needs no strategy code runs none. Consequence accepted: when an input is both breached and
  one the child would reject for identity (strategy name, config hash), the breach wins; the
  supervisor runs the planner's strategy-free input checks first, so a malformed input (for example
  `max_drawdown` outside [0, 1]) is still refused, never read as a breach.
- A child may report only a decision-level breach (`DECISION_BREACH_KINDS`, defined beside
  `RISK_BREACH_KINDS` as the kinds `validate_decision_weights` raises), and only where the verdict is
  to plan; any other kind, or any other result kind or warming flag, is `frozen_result_invalid`,
  never a halt. The supervisor also recomputes and compares the Phase A binding.
- The pending venue belief is answered with the supervisor's pre-belief verdict, so a drawdown or
  equity breach is reported one call before the belief read, exactly as in process; the frozen
  effect trace is now identical to the in-process one (the earlier extra belief read is gone).
- A supervisor-side refusal of its own input maps to `frozen_planner_rejected` with the planner's
  own `code: detail`, the same text a child's refusal would carry.
- `plan` validates and emits the weights as float64 in symbol order (after the dtype guards run on
  the strategy's own Series), the exact form the supervisor re-validates, so a float32 weight at a
  cap cannot pass the child and breach the supervisor. The in-process target-weight order becomes
  symbol order.
- Only a failed exec (or chdir into the bundle), which `subprocess` reports with that path as the
  error's `filename`, is the tenant's `frozen_launch_failed`; any other `OSError` (the invocation
  directory on the data volume, descriptors, reaping) affects every tenant and propagates as
  systemic. An entry module that cannot be stat'ed is `frozen_content_unsupported`, not a raw error.

## 2026-09-30 — Registry review fixes

- `ExecutionContract` and `CapacityLimit` store an int written into a float field as the equal float,
  so the qualified `config_hash` (from `asdict`) and the recorded frozen config (`model_dump`) agree;
  `config_hash` of all 25 repo strategies is unchanged (pinned). Without this, any such candidate
  would be refused at every intake forever.
- Story 1.3b preparation refuses a config that canonical NFC normalisation would change (decomposed
  Unicode) before publishing anything, instead of admitting content that can never tick.
- Raw `registry transition` to `forward_tested` and the go-live challenge/signature path refuse a
  frozen deployment before any identity hashing (`frozen_qualification_pending` /
  `frozen_live_unsupported`), closing a bypass of §9.
- `assert_clean_head` accepts well-formed orphaned `__pycache__` caches and cache-only directories
  (Python never imports sourceless bytecode from `__pycache__`); every other untracked entry is still
  refused, with the offending path class named. The main checkout had three such directories that
  would otherwise have blocked every intake.
