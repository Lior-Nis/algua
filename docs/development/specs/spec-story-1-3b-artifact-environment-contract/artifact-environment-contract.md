# Normative frozen artifact and environment contract

This companion defines the persisted and filesystem contract for Story 1.3b. It does not define
Story 1.3c's planner transport or activate any deployment.

## Contract vocabulary and versions

| Name | Exact value or meaning |
|---|---|
| frozen descriptor version | `1` |
| source kind | `frozen` |
| planner boundary version | `1`, the Story 1.3a logical contract |
| existing planner protocol version | the existing integer `PLANNER_PROTOCOL_VERSION`; preserved for current database compatibility |
| frozen wire identity | `{"name":"frozen-planner","version":1}`; reserved/stamped here and implemented in Story 1.3c |
| digest algorithm | SHA-256, rendered as 64 lowercase hexadecimal characters |
| source reference | full Git commit object ID of the current clean `HEAD` |
| locator | canonical relative POSIX path derived only from an object digest |

Canonical JSON is UTF-8 with sorted keys, compact separators, `ensure_ascii=False` and
`allow_nan=False`. Strings are NFC-normalized before validation. Duplicate JSON keys are invalid.
All schema objects reject missing and unknown fields.

## Identity graph

The four identity layers are deliberately non-cyclic:

1. `bundle_digest` commits to the canonical bundle inventory. The inventory contains exported Git
   source plus generated `resolved-config.json` and `protocol.json`; neither contains
   `bundle_digest`, environment identity or the outer descriptor.
2. `build_inputs_digest` commits to exact Git blob bytes and logical modes for `pyproject.toml`,
   `uv.lock` and `.python-version` at `source_ref`.
3. `environment_key` commits to `build_inputs_digest`, the existing `dependency_hash`, exact
   interpreter/platform facts and the normative installer identity/flags. `environment_digest`
   commits to that key, the installed inventory and the verified interpreter facts.
4. `manifest_digest` commits to the complete canonical frozen descriptor, including the bundle and
   environment digests and locators, qualified identity, configuration, asset inventory and protocol
   identities.

Consequences:

- changing source bytes, source mode, resolved configuration, planner boundary or frozen-wire stamp
  changes `bundle_digest` and `manifest_digest`;
- changing build inputs, dependency identity, interpreter, ABI, platform, installer identity or
  installed inventory changes `environment_key`, `environment_digest` and `manifest_digest`, but
  not `bundle_digest`;
- timestamps, enumeration order, staging names, absolute roots and filesystem mtimes enter no
  identity;
- implementations must publish literal golden vectors for all four digest layers.

Each digest preimage is canonical JSON with a distinct domain and version:

| Digest | `domain` | `version` |
|---|---|---|
| bundle | `algua.frozen-bundle` | `1` |
| build inputs | `algua.frozen-build-inputs` | `1` |
| environment key | `algua.frozen-environment-key` | `1` |
| installed inventory | `algua.frozen-installed-inventory` | `1` |
| environment | `algua.frozen-environment` | `1` |
| manifest | `algua.frozen-manifest` | `1` |

## Qualification and source selection

Preparation accepts a strategy name and performs this eligibility sequence:

1. resolve repository root and require `git rev-parse HEAD` to return a full commit OID;
2. require no tracked difference from `HEAD` and no untracked regular file, directory entry or link
   below `algua/` that could shadow exported source, except recognized generated bytecode derived
   from a tracked sibling;
3. recompute the existing code/config/dependency identity and load the current tradable strategy;
4. reject a model handle or non-empty assets as `frozen_assets_unsupported`, before reading any
   external asset path or bytes;
5. require the strategy to be a candidate and the newest passed eligible research gate for that
   strategy and identity to be unanchored and match the candidate entry;
6. capture the exact canonical resolved configuration and gate universe.

Slow Git, filesystem and environment work follows outside a SQLite write transaction. Immediately
before recording the descriptor, one short `BEGIN IMMEDIATE` transaction revalidates the strategy
stage, candidate entry, newest eligible gate, complete recomputed identity and the same clean full-OID
`HEAD`. Drift aborts as `frozen_source_drift`. The transaction inserts or byte-verifies only the
artifact row and commits. It creates no strategy deployment, allocation or transition and does not
consume the gate.

This cycle does not accept an arbitrary ref, branch name, abbreviated OID or detached historical
candidate. Verification never performs these Git checks.

## Git object export

Source inventory is derived from raw NUL-delimited Git output equivalent to:

```text
git ls-tree -r -z --full-tree <source_ref> -- algua
```

Every accepted entry is a blob with logical mode `100644` or `100755`. Blob bytes are read by object
ID, equivalent to `git cat-file blob <oid>`, never from a checkout path. Tree entries with mode
`120000` (symlink), `160000` (gitlink/submodule), an unsupported object type or any special mode are
rejected. Build-input blobs use the same object-only rule from the repository root.

Git output is parsed as bytes. A path must be valid UTF-8, NFC, non-empty and relative POSIX text.
Reject a NUL, backslash, absolute path, drive prefix, empty segment, `.` or `..` segment, trailing dot
or space in any segment, path longer than 1,024 UTF-8 bytes, and any exact, NFC or Unicode-casefold
collision. No path repair or platform-dependent normalization is allowed.

Protected bounds are:

| Bound | Value |
|---|---:|
| source entries | 10,000 |
| one source/generated file | 64 MiB |
| complete bundle bytes | 512 MiB |
| canonical path | 1,024 UTF-8 bytes |
| canonical descriptor JSON | 1 MiB |
| persisted sanitized diagnostic | 8 KiB |

Raising a bound requires protected review and a new contract version. An operational setting may
only tighten a bound.

## Source bundle

The bundle root contains:

```text
algua/...                 exact accepted Git blob bytes
_algua/resolved-config.json
_algua/protocol.json
```

`resolved-config.json` is the exact canonical configuration bound by `config_hash`.
`protocol.json` is canonical JSON containing the frozen descriptor version, planner boundary
version, existing integer protocol version and named frozen-wire identity. The reserved `_algua/`
namespace cannot collide with exported source.

The bundle inventory is an ordered array sorted by normalized UTF-8 path bytes. Each entry contains
`path`, logical Git/generated `mode`, `size` and the full file SHA-256. The bundle digest preimage
contains that inventory; directory entries are implicit. Logical `100644`/generated files publish as
`0444`, logical `100755` files as `0555`, and directories as `0555`. No bundle link or hardlink is
permitted. Verification rejects extra, missing, writable, wrong-mode or non-regular entries.

Bundle locator:

```text
frozen/bundles/sha256/<first-two-hex>/<bundle_digest>
```

The locator must equal the digest-derived value exactly. It is joined only to trusted
`Settings.data_dir`, then resolved/inspected component by component without following untrusted
links and containment-checked beneath the configured store root. A manifest cannot supply an
absolute or alternate locator.

## Build inputs and environment key

Exact bytes for `pyproject.toml`, `uv.lock` and `.python-version` come from `source_ref`. They are
private provisioning inputs, not bundle or published environment files. `.python-version` must
admit the already-running exact interpreter; automatic interpreter download is forbidden.

The environment key contains:

- `build_inputs_digest` and existing `dependency_hash`;
- Python implementation and full version;
- `sys.implementation.cache_tag`, SOABI and `sysconfig.get_platform()`;
- normalized OS/architecture facts used by compatible-wheel selection;
- exact uv version;
- the complete normative create/sync argument vectors below.

No mutable cache path, absolute interpreter path, host name or staging path enters the key.

## Environment construction

Provisioning occurs in a unique private build directory using the exact current interpreter. The
normative operations are equivalent to:

```text
uv venv --relocatable --python <exact-current-interpreter> --no-python-downloads <env>
uv sync --project <private-build-input-root> --active --locked --no-dev --no-default-groups
  --no-editable --no-install-project --no-install-workspace --no-install-local --no-build
  --no-python-downloads --link-mode copy --no-env-file --no-config --no-progress
```

The implementation must pin and test the exact argv supported by the repository's uv version; the
semantic flags above may be reordered only if the environment key and golden contract vector change
together. It supplies a scrubbed environment, sets `PYTHONDONTWRITEBYTECODE=1`, and does not expose
operational credentials or the repository as an import root.

The committed lock is authoritative. Path, directory, workspace, editable, local archive, VCS or
source-distribution-only dependencies are unsupported in this cycle. A compatible locked wheel may
be acquired during preparation. No resolution, version selection, upgrade or project install is
allowed. A missing compatible locked distribution is `frozen_environment_unavailable` and is the
only retryable frozen-preparation failure.

Before publication, run the environment interpreter isolated from the checkout and prove:

- reported implementation, full version, cache tag, SOABI and platform match the key;
- normalized installed distributions and importable regular files match the recorded inventory;
- no installed distribution is named `algua` and `importlib.util.find_spec("algua")` is `None`
  before the bundle is ever added to an import path;
- package files are regular, owned by the environment tree and not hardlinked to a cache;
- the only permitted symlinks are the exact interpreter-link set created by the relocatable venv,
  each with a validated target inside the environment or the exact keyed base interpreter;
- no other link, socket, FIFO, device, writable file or unexpected entry exists.

The installed inventory digest is over normalized distribution name/version plus every importable
relative file path, kind, logical executable bit, size and file digest. Generated bytecode is absent.
The environment descriptor binds this digest, the environment key and verified interpreter facts.

Environment locator:

```text
frozen/environments/sha256/<first-two-hex>/<environment_digest>
```

After publication and sealing, the interpreter at the final locator must repeat the isolated
identity/import test. This catches relocation failures before a descriptor can be recorded.

## Atomic publication and verification

Bundle and environment publication independently follow this protocol:

1. create a unique same-filesystem private staging directory with mode `0700` under a designated
   staging parent;
2. write/build using create-new semantics, then validate the complete canonical inventory;
3. seal files and directories to their required non-writable modes;
4. fsync file contents, directories and the staging parent bottom-up where supported;
5. acquire a per-digest advisory lock shared by all cooperating builders;
6. if the final locator exists, verify it completely and remove only this builder's exact staging
   directory; if verification fails, report corruption without overwrite or repair;
7. otherwise rename the owned staging directory to the absent final locator without replacement,
   then fsync the final parent chain;
8. verify the published object again, including final-location environment execution.

Use the repository's durable-fsync and flock primitives, but do not use any helper whose replacement
semantics can overwrite an existing object. A race loser verifies the winner. Same-UID hostile
replacement outside the cooperating lock remains the accepted no-sandbox residual.

On a handled failure, cleanup is restricted to the exact staging directory created and owned by the
attempt. A hard crash may leave a private incomplete staging directory but never a partial object at
a final locator. No startup or command path deletes unknown, published or unreferenced content.

Verification recomputes every digest and descriptor relation and checks paths, types, permissions,
hardlinks, permitted environment links, extra/missing entries and the final interpreter. It never
repairs or rebuilds content.

## Frozen manifest

The canonical outer manifest contains exactly:

| Field | Required content |
|---|---|
| `descriptor_version` | `1` |
| `source_kind` | `frozen` |
| `source_ref` | full qualified commit OID |
| `identity` | exact `code_hash`, `config_hash`, `dependency_hash` |
| `resolved_config` | canonical resolved configuration object |
| `universe_name` | qualifying gate universe or null |
| `bundle` | digest, exact digest-derived locator, canonical inventory digest/count/bytes |
| `environment` | key, digest, exact locator, build-input and installed-inventory digests, exact interpreter/platform/uv facts |
| `assets` | exactly `[]` |
| `planner_protocol_version` | existing integer protocol stamp |
| `planner_boundary_version` | `1` |
| `frozen_wire` | exact named/versioned identity above |

`manifest_digest` is computed over this object and is not embedded within it. Existing
`DeploymentManifest` denormalized columns must exactly agree with the frozen manifest:

- `source_kind`, `source_ref`, three artifact hashes, resolved configuration, universe, environment
  digest/interpreter fields, existing protocol version and canonical assets;
- `manifest_json` is the canonical frozen object and `manifest_digest` its exact digest.

Frozen parsing is typed and version-dispatched. Existing working-tree manifest bytes and verification
remain unchanged. No database migration is required unless implementation demonstrates a query that
cannot use the current immutable row and canonical JSON; any such change requires separate protected
schema review before implementation.

Recording uses a short write transaction and conflict-safe insert-or-byte-verification. If a row for
the digest exists, every immutable column and exact manifest byte must match. A database failure may
leave complete unreferenced bundle/environment objects; retry reuses them and resolves to the same
descriptor row. Verification can fetch a descriptor by `manifest_digest` without an active
deployment.

## Command surface

```text
algua deployment prepare NAME
algua deployment verify MANIFEST_DIGEST
```

`prepare` may write immutable store objects and one artifact-ledger row. `verify` is read-only and
offline: it performs no Git, uv, network, qualification or checkout access. Neither command creates
or retires a deployment, allocates capital, changes stage, invokes a planner, contacts a provider or
broker, or consumes a research gate.

A successful response includes only:

```json
{
  "ok": true,
  "strategy": "name",
  "artifact_id": 1,
  "manifest_digest": "...",
  "source_ref": "...",
  "bundle": {"digest": "...", "locator": "frozen/bundles/..."},
  "environment": {
    "key": "...",
    "digest": "...",
    "inventory_digest": "...",
    "locator": "frozen/environments/..."
  },
  "verified": true
}
```

Numbers and field presence follow the repository JSON convention. Errors use the standard envelope,
never raw stderr, absolute paths, URLs, credentials or a traceback. Diagnostics are sanitized and
bounded to 8 KiB.

Stable error codes:

| Code | Retryable | Meaning |
|---|---|---|
| `frozen_source_invalid` | no | invalid Git object, path, type, mode, size or unsupported build input |
| `frozen_source_drift` | no | clean HEAD, candidate, gate or current identity changed during preparation |
| `frozen_assets_unsupported` | no | source-only lane was not satisfied |
| `frozen_bundle_corrupt` | no | existing/published bundle fails canonical verification |
| `frozen_environment_unavailable` | yes | a selected compatible locked distribution cannot currently be acquired |
| `frozen_environment_incompatible` | no | unsupported lock/dependency/interpreter/platform or relocatability contract |
| `frozen_environment_corrupt` | no | existing/published environment fails inventory or interpreter verification |
| `frozen_descriptor_conflict` | no | stored row/columns disagree with canonical descriptor bytes |
| `artifact_not_found` | no | requested manifest digest has no artifact row |

`db_unavailable` retains its existing retry policy. No other frozen error is retryable.

## Required verification matrix

- Literal digest vectors for bundle, build inputs, environment key/inventory/environment and manifest.
- Enumeration, root and mtime invariance; one-byte, logical-mode, config, protocol, build-input,
  interpreter, ABI and platform sensitivity at the correct identity layer.
- Invalid UTF-8/NFC, traversal, separator, portability, collision, symlink, gitlink, special-entry and
  protected-limit rejection.
- Same-digest and different-digest concurrent builders; interruption/fault injection after every
  write, fsync, seal, lock, rename, final verify and database boundary.
- Valid existing-object reuse and fail-closed corrupt, partial, writable, wrong-mode, link/hardlink,
  extra and missing-object cases without overwrite.
- Exact uv argv/environment tests, locked-wheel unavailability, forbidden resolution/local/source
  dependency and interpreter incompatibility.
- Environment sharing only on equal complete keys; inventory drift, Algua install/import, checkout
  leakage, writable files and forbidden links fail.
- Final-locator interpreter test and offline verification after removing `.git`/checkout and making
  uv/network unavailable.
- Asset rejection before path dereference with no object or descriptor row.
- Database rollback leaves only complete reusable unreferenced objects; retry records the same bytes
  and ID; no slow operation occurs inside a write transaction.
- Exact JSON success/error envelopes, relative locators, bounded diagnostics and stable retry flags.
- Zero deployment, allocation, transition, gate-consumption, planner, provider or broker effects.
- Retirement and repeated verification never delete content; working-tree descriptor bytes and all
  Story 1.3a parity behavior remain unchanged.

## Protected implementation seams

Prefer focused modules such as `registry/artifact_contract.py`, `registry/frozen_source.py`,
`registry/artifact_store.py`, `registry/planner_environment.py`,
`registry/artifact_preparation.py` and `cli/deployment_cmd.py`. Keep I/O out of `algua/contracts`;
move or alias shared protocol constants there only when necessary so registry code never imports
runtime modules. Do not grow the size-pinned deployment or command modules.

New digest, verification, publication, descriptor-recording and error-policy modules are
integrity-critical. Add them to root `CODEOWNERS` and to the repository hygiene protection test.
Any migration or modification to current activation/intake, paper/live runtime, broker, capital or
authorization surfaces is outside Story 1.3b and requires a new approved scope.
