# Decision log

## 2026-10-01 — Initial distillation

Inputs: Story 1.2 (legacy cohort), Stories 1.3a–1.3d, the artifact-freeze design, the production
registry (18 legacy paper tenants, schema v48, read-only) and the owner decisions of 2026-10-01.

- One command, one phase per invocation (`pending_flat` drain or atomic `exited`), so an interrupted
  run is always repeated rather than resumed, and every intermediate state is truthful.
- Drain is per strategy: the tenant's own open orders and exact ledger quantities, never an
  account-wide cancel, because 18 tenants share one paper account.
- The kill switch is tripped first in the drain so no paper cycle re-enters a draining tenant.
- Exit goes through the existing transition machinery (`paper → candidate → backtested`, or
  `→ retired`) with `reason=legacy_migration`, so no new lifecycle edge exists and the candidate row
  written on the way carries NULL hashes (never admissible to intake).
- State keyed by strategy name (drawdown peak, kill switch) is reset in the exit transaction (owner
  decision O5); paper NAV realized history is kept and documented.
- No schema change; three stable non-retryable codes.
- Owner decisions (O1 disposition, O2 holdout policy, O3 timing, O5 kill switch) live in the story
  and runbook, not in code.

## 2026-10-01 — Readiness verdict and rescope

The readiness review judged the first contract NOT READY (2 blockers, 3 major): the single exit
transaction could not be composed from today's self-committing helpers, ledger float dust blocked six
tenants forever, the drain/exit decision had no open-order source, re-runs were not idempotent and the
operator lock was unnamed.

The same day the owner decided to kill every legacy strategy ("kill all strats"), superseding O1–O3
and O5. That removes the requalification and re-admission requirements that made the command
necessary. The cohort exits through the existing `paper flatten` and `paper -> retired`, and the
story shrinks to the three defects that blocked them on the shared account:
- `paper flatten` cancelled account-wide, so sequential flattens while the market was closed would
  cancel each other's queued offsets (it now uses the existing scoped cancel);
- cross-tenant ledger residuals from notional fills (#677) made a full sale exceed what the account
  held, and a sub-$1 buy-back was refused mid-loop (paper long offsets are capped at the ledger's
  account net; sub-minimum residuals are skipped);
- the bench flatness check demanded an exact zero (it accepts the same sub-minimum residuals).

The broker's `submit_offset` stays strict (an emergency liquidation the account cannot fully fill
still raises); the cap is ledger-derived, never broker-held, because a shared account's holdings are
not one tenant's.
