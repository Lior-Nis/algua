# pip-audit advisory allowlist  (consumed by .github/workflows/security.yml)
#
# One vulnerability ID per non-comment line. Each entry is a KNOWN advisory that
# cannot currently be remediated by a lockfile bump, with a documented reason.
# Keep this list MINIMAL and review the entries at every dependency upgrade.
#
# NOTE ON SCOPE: pip-audit's --ignore-vuln suppresses an advisory GLOBALLY (it is
# not package-scoped). Because the list is small and reviewed, that is acceptable;
# do not add an ID here without confirming which package/version it applies to.
#
# Format for each active entry (all lines above the ID are comments):
#   # <package> <version> — <one-line reason> — tracking: <issue/url> — review: <YYYY-MM>
#
# BEFORE ADDING AN ENTRY, TRY THIS FIRST:
#
#     uv lock --upgrade-package <name>
#
# `uv lock` alone does NOT move a transitive dependency: it keeps the existing pin if the
# constraints still permit it. Every entry that used to live in this file said the package
# "cannot be upgraded without a major mlflow-tree bump" and would "clear when mlflow is next
# major-upgraded". That was never true. On 2026-09-13, naming the packages explicitly moved
# starlette 0.52.1 -> 1.6.0, cryptography 46.0.7 -> 50.0.1 and fastapi 0.136.3 -> 0.141.1 in one
# resolve, clearing all nine suppressed advisories at once. Nothing was blocking them but the
# absence of that flag.
#
# An allowlist entry is a claim that an advisory is UNFIXABLE. Verify the claim with the command
# above before you make it, or this file quietly becomes the place vulnerabilities go to be
# forgotten.
#
